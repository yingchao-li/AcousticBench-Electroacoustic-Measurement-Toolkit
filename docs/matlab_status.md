## Intended commands (to be run later with MATLAB R2021b+)

```
# From the repository root, with matlab/ on the path
matlab -batch "addpath('matlab'); run_all_tests"
matlab -batch "addpath('matlab'); run_cross_language_export"

# Exactly how the Python E15 runner invokes the export script:
matlab -batch "cd('<repo>'); run('matlab/run_cross_language_export.m');"

# Interactive GUI (desktop session)
matlab -r "addpath(genpath('matlab')); AcousticBenchGUI;"
```

The literal command `matlab -batch "run_cross_language_export"` from the
repository root only works when `matlab/` is on the MATLAB search path
(e.g. `matlab -sd matlab -batch "run_cross_language_export"`, or a root
launcher that adds `matlab/`); the recommended unattended form is the
`addpath('matlab')` or `run('matlab/...')` variant. The export script
resolves the repository root from its own file location (with `which`/`pwd`
fallbacks), so the working directory does not matter once it has been found.

## E15 cross-language contract (implemented, not executed)

Input: `results/validation/matlab_inputs.mat` (written by the Python side).
The file actually generated by the Python exporter was inspected and contains
the **parallel-array form**: `ids` (cellstr 25x1), `category` (cellstr 25x1),
`fs` (1x25), `input`/`output`/`clean_reference` (192000x25) and `tone_hz`
(1x25); the 25 signals are 7 gain + 7 snr + 7 thd + 4 frequency-response
cases.  A 1xN struct array `signals` is accepted too; its elements have
`id` (char, e.g. `'gain-0001'`), `category` (`gain`/`snr`/`thd`/
`frequency_response`), `fs`, `input`, `output`, `clean_reference`,
`tone_hz` (NaN for FR), `gain_db`, `snr_db`, `thd_percent` (scoring only) and
`freq_start_hz`/`freq_end_hz`.

Output: `results/validation/matlab_reference.csv` with the exact header
`test_id,quantity,value,unit`, values printed with `%0.17g`, directories
created if missing. Rows:

- one row per synthetic signal, using `test_id = signals(k).id` and the
  category-specific quantity: `gain_db` (dB), `snr_db` (dB) or
  `thd_percent` (%); `frequency_response` cases are omitted because the
  input file has no analytic reference response needed for `fr_mae_db`
  (the contract allows omission; emitting a NaN row would additionally create
  a vacuous zero-sample `fr_mae_db` comparison that the Python report counts
  as failed).  With the current input the script therefore writes 163 rows
  (142 dataset + 21 synthetic) instead of the 167 expected ids; the 4 missing
  ids are the FR placeholders whose expected value is NaN in
  `expected_synthetic_values.csv`;
- `hha_band:<device_code>:<band_center_hz>` (`hha_band_db`, dB), 36 rows;
- `reoig_band:<family>:<band_center_hz>` (`reoig_db`, dB), 63 rows
  (band level of M_ls2edM minus band level of M_REUR, i.e. a ratio of mean
  band powers);
- `ptpe_hha_band:<family>:<band_center_hz>` (`ptpe_hha_db`, dB), 36 rows;
- `delta_t_125:<family>` (`delta_t_db`, dB), 7 rows.

Octave bands use centres 63, 125, 250, 500, 1000, 2000, 4000, 8000, 16000 Hz
and the exact definitions documented in `matlab/README.md` and in the
`referenceMetrics` / `run_cross_language_export` H1 help blocks.

## What was actually verified here (and what was not)

**Performed:**

1. **Static self-review** of all 46 `.m` files with a purpose-written Python
   checker: ASCII safety; each file's first code line is a `function`/
   `classdef` whose name matches the file name; no Python-isms (`def`,
   `True/False/None`, `#`, `**`, `!=`, ...); no banned toolbox calls; block
   balance for `function/if/for/while/switch/try/arguments/classdef/methods`
   (with correct handling of the `end` index); delimiter balance.
   Result: **0 problems**. This is source-level checking only - it cannot
   prove MATLAB parsing or runtime correctness.
2. **Definition-level cross-check in Python (not MATLAB)**: the
   `referenceMetrics` formulas were re-implemented independently in Python
   and compared with the Python production expected table for E15.  All
   **142/142 dataset rows match to <= 1.4e-14 dB** (this check caught and
   fixed one definition mismatch: the band REOIG is the band level of
   M_ls2edM minus the band level of M_REUR, i.e. a ratio of mean band powers,
   not a mean of pointwise dB ratios).  The MATLAB synthetic estimator
   definitions were also re-implemented in Python and applied to the actual
   `matlab_inputs.mat` signals: gain <= 3.6e-15 dB (E15 tolerance 0.01 dB),
   SNR <= 0.0085 dB (tolerance 0.05 dB), THD <= 1.5e-12 percentage points
   (tolerance 0.01 pp).  This validates the *definitions* used by the MATLAB
   code, not the MATLAB code itself.
